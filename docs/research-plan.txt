R&E 이창민 담당 파트 README

연구 주제
적록색약자를 위한 개인화 선택적 AI 색보정

============================================================
1. 내 핵심 역할
============================================================

내 역할은 특정 사용자가 혼동하는 색쌍을 입력받아,
두 색을 구별 가능하게 만들면서도 원본과의 색 변화량이 최소가 되도록
보정하는 알고리즘을 개발하는 것이다.

전체 순서

1) Machado 색각이상 시뮬레이터 구현
2) 두 색의 혼동 여부 판정
3) 규칙 기반 최소 색이동 알고리즘 구현
4) 위 기능을 합쳐 baseline 완성
5) baseline 검증 후 AI 색보정 모델로 확장

※ 현재는 AI부터 만들지 않는다.
※ 먼저 AI 없이 작동하는 규칙 기반 baseline을 완성한다.


============================================================
2. 1단계 - Machado 색각이상 시뮬레이터
============================================================

목표:
RGB 색상과 사용자 파라미터를 입력하면,
해당 색각이상 조건에서 예상되는 색상을 출력한다.

입력:
- RGB 색상
- cvd_type: protan / deutan
- simulation severity: 0.0 ~ 1.0

출력:
- simulated RGB

예상 함수 형태:

simulate_color(rgb, cvd_type, severity)

예시:

입력
rgb = (220, 50, 50)
cvd_type = "deutan"
severity = 0.6

출력
simulated_rgb = (...)

해야 할 검증:
- severity = 0이면 원본과 동일하거나 거의 동일한가?
- severity를 0.0 → 1.0으로 증가시켰을 때 결과가 자연스럽게 변화하는가?
- protan과 deutan 결과가 서로 다르게 나타나는가?
- 공식 Machado 행렬 및 처리 순서를 정확하게 사용했는가?


============================================================
3. 2단계 - 두 색의 혼동 여부 판정
============================================================

목표:
두 색 A, B가 특정 사용자에게 실제로 혼동될 가능성이 있는지 판정한다.

예상 함수 형태:

is_confusing(color_a, color_b, cvd_type, severity, threshold)

처리 과정:

색 A, 색 B
→ 원본 색차 계산
→ 두 색에 Machado 시뮬레이션 적용
→ 시뮬레이션 후 색차 계산
→ 혼동 여부 판정

혼동 판정 기본 조건:

1) 원본에서는 두 색이 충분히 다르다.
2) 색각이상 시뮬레이션 후에는 두 색의 차이가 임계값 이하로 감소한다.

출력 예시:

{
    "original_distance": ...,
    "simulated_distance": ...,
    "confusing": True/False
}

주의:
- 원래부터 비슷한 두 색은 "색각이상 때문에 혼동되는 색"으로 처리하지 않는다.
- threshold 값은 처음부터 임의로 확정하지 않고 이후 실험을 통해 조정한다.


============================================================
4. 3단계 - 최소 색이동 알고리즘
============================================================

목표:
혼동되는 두 색을 구별 가능하게 만들되,
원본에서 가능한 적게 변화시키는 보정색을 찾는다.

예상 함수 형태:

find_minimum_correction(
    color_a,
    color_b,
    cvd_type,
    severity,
    target_threshold
)

비교해야 할 경우:

A) 색 A만 이동
B) 색 B만 이동
C) A와 B를 모두 조금씩 이동

세 경우 중

- 시뮬레이션 후 두 색이 구별 가능하고
- 전체 색 변화량이 가장 작은 결과

를 선택한다.

목표를 개념적으로 표현하면:

구별 가능 조건:
D_CVD(A*, B*) >= target_threshold

최소화 목표:
D(A, A*) + D(B, B*) → 최소

색 이동은 OKLab 공간에서 계산한다.

보정량 출력 예시:

{
    "delta_A": (dL_A, da_A, db_A),
    "delta_B": (dL_B, da_B, db_B),
    "corrected_A": ...,
    "corrected_B": ...,
    "total_color_change": ...
}

초기 버전:
- grid search 또는 단순 최적화 방식으로 구현
- 처음부터 AI를 사용하지 않음

중요:
- 보색으로 강제로 바꾸는 것이 목적이 아니다.
- 사용자가 구별할 수 있게 되는 "가장 가까운 색"으로 이동시키는 것이 목적이다.
- 보정 후 새로운 다른 색과 혼동되는 재혼동은 palette 인자로 검사한다.
  주의: 이 검사는 is_confusing()으로 대체할 수 없다. is_confusing()은
  "원본에서는 달랐는가"를 함께 묻기 때문에, 보정이 만들어낸 새 충돌을
  "색각이상 탓이 아니다"라는 이유로 통과시킨다. 재혼동 제약은 시뮬레이션
  후 거리만 보는 별도 조건이어야 한다.
- sRGB에서 표현 불가능한 색이 생성되지 않도록 gamut도 확인한다.


============================================================
5. 4단계 - 규칙 기반 baseline 완성
============================================================

최종 입력:

- color_A
- color_B
- cvd_type
- severity
- confusion_threshold

전체 처리:

1. 두 색의 혼동 여부 판정
2. 혼동하지 않음
   → 원본 그대로 반환
3. 혼동함
   → 최소 색이동 탐색
4. 보정 결과 반환

1차 baseline의 최종 목표:

두 색 + 사용자 파라미터
→ 혼동 여부 판정
→ 혼동되지 않으면 그대로 유지
→ 혼동되면 구별 가능한 최소 변화 보정색 출력


============================================================
6. 반드시 해볼 핵심 테스트
============================================================

테스트 A
- 빨강 + 파랑
- 특정 사용자에게 혼동되지 않으면 두 색 모두 그대로 유지

테스트 B
- 테스트 A와 완전히 동일한 빨강 + 초록
- 특정 사용자에게 혼동된다면 필요한 색만 최소 이동

핵심 확인:

"같은 빨강이라도 혼동 상대가 없으면 보정하지 않고,
실제로 혼동되는 상대 색이 존재할 때만 선택적으로 보정하는가?"

이 테스트는 연구의 핵심 차별성을 확인하는 가장 중요한 초기 실험이다.


============================================================
7. AI 단계는 baseline 성공 후 진행
============================================================

baseline이 정상적으로 작동한 뒤에 AI 모델을 개발한다.

예정 구조:

입력
- 이미지
- 사용자 type
- simulation severity
- 혼동 영역 정보

→ U-Net 또는 Encoder-Decoder
→ 각 영역의 OKLab 이동량 예측
→ 보정 이미지 생성

AI의 목적:
규칙 기반 탐색을 단순히 복제하는 것이 아니라,
이미지 전체의 색 분포와 사용자 특성을 고려하여
구별성을 확보하면서 최소 색 변화와 재혼동 방지를 동시에 학습한다.

주요 손실 후보:
- L_sep       : 혼동 색쌍 구별
- L_preserve  : 원본 색 보존
- L_reconf    : 새로운 혼동 방지
- L_gamut     : sRGB 색역 유지
- 필요 시 L_smooth / temporal consistency 추가

현재 구현 실행:

주변 색까지 고려해 재혼동을 막으려면 --palette 를 쓴다.

자동 테스트:

python -m unittest -v

주의:
- tau_high, tau_low, tau_target은 아직 실험 변수이며 사용자 데이터로 조정해야 한다.
  단 tau_high >= tau_low 는 코드가 강제한다. 이 관계가 뒤집히면 원래부터
  비슷한 색쌍이 "색각이상 때문에 혼동되는 쌍"으로 잘못 분류되기 때문이다.
- 최소 색이동은 OKLab radial grid로 넓게 찾은 뒤, 각 전략에서 이동량이
  작은 여러 후보 주변의 8-bit RGB 정수색을 합쳐 다시 확인한 multi-start
  탐색이며, 양쪽 이동은 개선이 멈출 때까지 반복 정밀화하는 근사 최적해이다.
  대표 빨강-초록
  검증 색쌍((192,32,32)/(64,128,0), deutan, severity 1.0, target 10)의
  총 이동량은 step 0.04 -> 0.050330, 0.02 -> 0.049668,
  0.01 -> 0.049668, 0.005 -> 0.049668이었다.
  기본값은 보수적으로 0.005를 사용한다. 이 값은 해당 검증 색쌍에서
  전체 8-bit B 후보를 대조해 얻은 B-only 최솟값과 일치하지만, 모든
  색쌍에 대한 수학적 전역 최적해를 보장한다는 뜻은 아니다.

  이전 단일 시작점 방식에서 step에 따라 A_only/B_only가 진동하던
  (142,160,45)/(36,169,113) 사례는 multi-start 정밀 탐색 뒤
  step 0.04/0.02/0.01/0.005 모두 B_only 0.001336으로 일치한다.
  이 회귀 사례 하나만으로 전체 색공간에서 step 영향이 사라졌다고
  일반화하면 안 된다.

  더 넓은 표본의 step 편차는 다음 명령으로 측정한다. 결과 JSON에는
  random seed, 실제 색쌍, 실행 환경, 편차 계산식이 함께 저장된다.

  python benchmark_search.py --pairs 30 --output ../results/search_benchmark.json

  현재 고정 30쌍 결과는 평균 편차 0.0176%, 최대 0.5267%, 5% 초과 0건,
  비단조 0건이다. 30개 색쌍을 세 step으로 반복 탐색하므로 현재 환경에서
  약 8분이 걸린다. 이 표본 결과를 전체 색공간의 보장으로 일반화하지 않는다.
  논문에 수치를 쓸 때는 생성된 JSON을 연구 자료와 함께 보관한다.
- 탐색에 실패해도 max_shift를 키우는 것은 거의 효과가 없다. sRGB gamut이
  먼저 후보를 제한하기 때문이다 (max_shift 0.45 이상에서 후보 수 포화).
  step을 줄이거나 direction_grid_radius를 늘리는 쪽이 맞다.
- target_threshold를 과도하게 크게 잡으면 색상 자체가 파괴된다. 결과의
  hue_shift_A_degrees / hue_shift_B_degrees 로 확인할 수 있다.
- 재혼동 제약은 "보정이 새 충돌을 만들지 않는다"를 보장한다. 원래 장면에
  이미 존재하던 충돌까지 해결하지는 않는다. 그것은 두 색 baseline의
  범위를 벗어나며 팔레트 전체 최적화가 필요하다.
- 실제 이미지 연결과 AI 단계는 1차 두 색 baseline 이후 작업이다.


============================================================
9. 1차 완료 기준
============================================================

아래가 모두 되면 내 1차 역할은 성공한 것으로 본다.

1. RGB 두 색과 사용자 파라미터를 입력할 수 있다.
2. 두 색이 해당 사용자에게 혼동되는지 계산할 수 있다.
3. 혼동되지 않는 색은 바꾸지 않는다.
4. 혼동되는 색은 구별 가능한 수준까지만 이동시킨다.
5. A만/B만/양쪽 이동 중 총 변화량이 가장 작은 결과를 선택한다.
6. 보정 전후 색차와 총 색 변화량을 수치로 출력한다.
7. 보정 결과가 sRGB 색역을 벗어나지 않는지 확인한다.
