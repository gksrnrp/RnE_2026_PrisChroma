# R&E Codex Context

프로젝트명:
적록색약자를 위한 개인화 선택적 AI 색보정

작성 목적:
이 파일은 ChatGPT와 진행한 R&E 설계 대화를 Codex에 전달하기 위한 프로젝트 컨텍스트이다.
Codex는 아래 내용을 프로젝트의 현재 합의사항으로 간주하고, 임의로 연구 방향을 바꾸지 말 것.
불확실한 부분은 구현 전에 TODO 또는 실험 변수로 남길 것.

======================================================================
0. 최종 목표
======================================================================

최종적으로 적록색각이상 사용자가 휴대폰/컴퓨터 등 디지털 기기를 사용할 때,
화면 전체를 강하게 바꾸거나 보색으로 치환하지 않고,
"그 사용자에게 실제로 혼동되는 색 관계가 존재하는 영역만"
선택적으로 보정하고 싶다.

핵심 목표:
- 사용자마다 다른 색 혼동 특성을 반영
- 혼동 상대가 없는 색은 그대로 유지
- 혼동 상대가 있을 때만 선택적으로 보정
- 보색처럼 크게 바꾸는 것이 아니라
  "사용자가 구별 가능한 가장 가까운 색"으로 최소 이동
- 원본 색감/자연스러움 유지
- 보정으로 인해 새로운 혼동(re-confusion)이 생기지 않게 함
- 최종적으로는 실시간 디지털 화면 보정으로 확장

연구 질문:
"색각이상 사용자의 유형과 simulation severity를 고려하여 이미지 내 혼동 색의 관계를 탐지하고,
구별 가능한 최소한의 색 이동을 학습하는 것이 기존 고정 색변환 방법보다
색 구별성을 유지하면서 원본 왜곡과 재혼동을 줄일 수 있는가?"

3. 이창민 담당 범위 - 현재 가장 중요한 부분
======================================================================

현재 Codex가 우선 구현해야 하는 것은 아래 4단계다.

1) simulate_color()
2) color_distance()/deltaE
3) is_confusing()
4) find_minimum_correction()

AI는 baseline이 정상 작동한 뒤 시작한다.

----------------------------------------------------------------------
3-1. Machado 시뮬레이터
----------------------------------------------------------------------

목표 함수 예시:

simulate_color(rgb, cvd_type, severity)

입력:
- rgb: (R,G,B), sRGB
- cvd_type: "protan" 또는 "deutan"
- severity: 0.0 ~ 1.0

출력:
- simulated_rgb

주의:
- Machado 2009 모델 사용
- Brettel은 dichromat 중심이라 연속 severity 개인화에 부적절하여 최종 채택하지 않음
- Machado 공개 3x3 행렬 테이블 사용
- severity 0.1 간격 행렬을 선형 보간
- RGB 처리 순서(감마/linear RGB 여부 포함)를 원 논문/저자 구현과 맞춰 검증할 것
- severity=0이면 원본과 동일/거의 동일해야 함
- severity 증가 시 결과가 자연스럽고 연속적으로 변해야 함
- protan/deutan 결과가 달라야 함
- 공식 행렬 출처 주석 필수

중요 용어:
severity는 "의학적 중증도"가 아니라
"해당 사용자의 색 지각을 가장 잘 근사하는 Machado simulation severity"로 정의한다.

개인 파라미터는:
(type, simulation severity)

이며,
완전한 개인 지각 모델이 아니라 "개인화를 위한 1차 근사 모델"이다.

----------------------------------------------------------------------
3-2. 두 색 혼동 판정
----------------------------------------------------------------------

목표 함수:

is_confusing(color_a, color_b, cvd_type, severity, threshold/params)

기본 흐름:

색 A, B
→ 원본 색차 계산
→ Machado(A), Machado(B)
→ 시뮬레이션 후 색차 계산
→ 혼동 여부 판단

혼동 쌍 기본 조건:

1. 원본에서는 두 색이 충분히 다름
2. 시뮬 후에는 두 색의 차이가 일정 임계값 이하로 감소

개념:

D_original(A,B) > tau_high
AND
D_simulated(A,B; type,s) < tau_low

이면 "색각이상으로 인해 혼동되는 색쌍" 후보.

주의:
- 원래부터 비슷한 색은 색각이상 때문에 생긴 혼동으로 처리하지 않음
- tau_high, tau_low, tau_target은 아직 확정값 아님
- 실험 변수로 남길 것
- 탐지/평가에서는 ΔE00(CIEDE2000)를 사용 가능
- 학습 loss에서는 ΔE00 직접 사용하지 않고 OKLab 유클리드 거리 사용 예정

출력 예시:

{
  "original_distance": ...,
  "simulated_distance": ...,
  "confusing": True/False
}

----------------------------------------------------------------------
3-3. 최소 색이동 알고리즘 (규칙 기반 baseline 핵심)
----------------------------------------------------------------------

목표:

혼동되는 색 A,B에 대해 보정색 A*, B*를 찾는다.

조건:
- 사용자 시뮬레이션 상에서 A*, B*가 구별 가능해야 함
- 원본 A,B에서의 총 색 변화량은 최소여야 함

수학적 개념:

D_CVD(A*, B*) >= tau_target

while minimizing:

D(A, A*) + D(B, B*)

세 경우 모두 비교:
A) A만 이동
B) B만 이동
C) A와 B 둘 다 이동

최종적으로 총 색 변화량이 최소인 결과 선택.

색 이동 공간:
- OKLab 권장
- 모델/알고리즘 출력: (ΔL, Δa, Δb)
- "파랑/채도/명도 세 경로로만 이동" 같은 고정 규칙 사용하지 않음
- 이동 방향은 자유롭게 허용

초기 구현:
- brute force/grid search 또는 간단한 numerical optimization 허용
- 먼저 정확성과 해석 가능성을 우선
- 이후 최적화 가능

출력 예시:

{
  "delta_A": (dL_A, da_A, db_A),
  "delta_B": (dL_B, da_B, db_B),
  "corrected_A": ...,
  "corrected_B": ...,
  "total_color_change": ...
}

중요:
- 보색으로 강하게 바꾸는 것이 목적이 아님
- 구별 가능 조건을 만족하는 "가장 가까운 색"이 목적
- sRGB gamut 밖 색 금지/패널티
- 보정 후 새로운 혼동(re-confusion) 검사 필요

----------------------------------------------------------------------
3-4. 규칙 기반 baseline의 완료 조건
----------------------------------------------------------------------

입력:
- color_A
- color_B
- cvd_type
- severity
- confusion threshold

처리:
1. 혼동 여부 판정
2. 혼동되지 않으면 원본 유지
3. 혼동되면 최소 색이동 탐색
4. 보정 전/후 거리 및 총 색 변화량 출력

1차 baseline 성공 기준:
- 두 색과 사용자 파라미터 입력 가능
- 혼동 여부 계산 가능
- 혼동되지 않는 색은 안 건드림
- 혼동되는 색은 구별 가능한 최소 수준까지만 이동
- A만/B만/양쪽 이동 중 최소 변화 선택
- 보정 결과가 sRGB gamut 안에 있음
- 보정 전후 수치 출력

4. 핵심 대조 실험
======================================================================

반드시 유지할 중요한 실험:

Image A:
[빨강] [파랑]

Image B:
[동일한 RGB의 빨강] [초록]

조건:
- 두 이미지의 빨강 RGB는 완전히 동일해야 함

원하는 결과:

Image A:
해당 사용자에게 혼동 상대 없음
→ 빨강 유지

Image B:
빨강-초록이 해당 사용자에게 혼동
→ 필요한 색만 최소 이동

핵심 검증 질문:
"같은 빨강이라도 혼동 상대가 없으면 보정하지 않고,
실제로 혼동되는 상대 색이 존재할 때만 선택적으로 보정하는가?"

이 실험은 "색 자체"가 아니라 "색 관계"를 본다는 연구 차별성을 보여주는 가장 중요한 초기 실험이다.

======================================================================
5. 이미지/영역 단위 확장
======================================================================

최종 baseline은 색 두 개가 아니라 실제 이미지에 적용해야 한다.

예정 흐름:

이미지
→ SLIC 영역 분할
→ 각 영역 대표색 추출
→ 영역쌍 생성
→ 사용자 파라미터로 혼동 판정
→ 혼동 영역쌍만 최소 색이동
→ 보정 이미지

영역쌍 정보 예시:

{
  region_A,
  region_B,
  confusion_score,
  spatial_relation
}

관계 판단:
- 1차 모델은 공간 거리 기반
- d_max를 파라미터로 둠
- 가까운 영역부터 비교
- d_max=∞이면 전역 비교(O(N^2))

주의:
- 의미적으로 관련되지만 멀리 떨어진 범례↔그래프 선 등은 현재 1차 모델의 한계
- 이 문제를 "완전히 해결"했다고 주장하지 말 것
- 향후 semantic relation/GNN 확장 가능

======================================================================
6. SLIC 관련 주의사항
======================================================================

SLIC은 전체 파이프라인의 큰 병목 가능성.

문제:
- 얇은 그래프 선
- 작은 글씨
- 작은 UI 아이콘
- 범례
가 배경과 병합될 수 있음.

따라서:
- n_segments 민감도 실험 필요
- 후보: 100/200/300/500/800
- 실패 시 Felzenszwalb, mean-shift, Region Growing, 색 양자화 등 대체 가능

초기에는 SLIC가 완벽해야 한다고 가정하지 말 것.

======================================================================
7. AI 단계 (baseline 이후)
======================================================================

AI 구조 후보:

입력:
- 이미지
- 사용자 type
- simulation severity
- 혼동 영역 정보

→ Encoder (경량 CNN/U-Net)
→ FiLM으로 (type,s) 조건화
→ Decoder
→ 픽셀별 색 이동량 맵 (H×W×3)
→ SLIC pooling
→ 영역별 (ΔL,Δa,Δb)
→ 보정 이미지

중요:
AI가 기존 baseline의 출력 이미지를 GT로 배워서는 안 됨.
baseline은 경쟁자/비교군이다.

AI 학습은:
"simulator-driven self-supervised learning"
즉, 정답 보정 이미지 없이
Machado 시뮬레이터와 목적함수로 직접 최적화한다.

======================================================================
8. AI 손실 함수 (현재 v5 설계)
======================================================================

L =
λ1 * L_sep
+ λ2 * L_preserve
+ λ3 * L_smooth
+ λ4 * L_reconf
+ λ5 * L_gamut

L_sep:
- 기존 혼동쌍을 사용자 시뮬레이션 상에서 충분히 분리
- hinge 형태
- 목표치 도달 후 더 벌리지 않음
- 학습 시 OKLab 거리 사용

예:
max(0, tau_target - D_OKLab(Sim(corrected_i), Sim(corrected_j)))

L_preserve:
- 원본과 총 색 변화량 최소화
- 면적 가중 가능

L_smooth:
- 경계 이질감 억제
- 모든 인접 영역에 무조건 강하게 걸면 L_sep과 충돌 가능
- 추후 색/질감 유사도 기반 가중 고려

L_reconf:
- "원래 혼동되지 않았던 쌍이 보정 후 새로 혼동될 때만" 벌점

정확한 개념:

was_confused = D_sim_before < tau_low
now_confused = D_sim_after < tau_low

if not was_confused and now_confused:
    penalty

원래부터 혼동이던 쌍을 못 고친 것은 L_sep의 역할이므로 중복 벌점 금지.

L_gamut:
- OKLab→sRGB 후 [0,1] 범위 밖으로 나간 양에 벌점
- clipping으로 AI 의도색과 실제 출력색이 달라지는 문제 방지

11. 개인화 실험
======================================================================

팀원 중 실제 적록색각이상 사용자가 있음.

실험 아이디어:
- 여러 색쌍에서 실제 구별 가능/불가능 경계를 측정
- 단순 "같아 보이냐"보다 forced-choice 형식 권장
- 예: 3개 중 2개 동일, 1개만 다르게 하고 다른 색 선택
- 색차를 줄여가며 threshold 측정

그 후:
P/D × Machado severity를 탐색하여
실제 사용자 응답을 가장 잘 설명하는 (type, severity)를 선택.

주의:
- 이시하라는 색각이상 선별/유형 추정용
- P/D를 임상적으로 확정했다고 주장하지 않음
- severity는 의학적 중증도가 아님
- 한 명의 사용자를 전체 적록색각이상자에게 일반화하지 않음
- 사례/pilot 검증으로 표현
- 연구용 피험자 데이터는 지도교사와 윤리/동의 절차 확인

======================================================================
12. 평가의 가장 큰 위험: 순환성
======================================================================

문제:
Machado로 학습하고
Machado로 혼동을 찾고
Machado로 평가하면
"Machado에 잘 맞춘 모델을 Machado로 평가"하는 순환 구조가 됨.

대응:
A. Machado 기반 시뮬 평가
B. Brettel/Viénot 등 다른 시뮬레이터 교차 평가
C. 실제 색각이상 사용자 평가

주의:
- Brettel은 주로 dichromat 검증에 적합하므로 중간 severity 전 구간 검증에는 한계
- 실제 사용자 평가가 가장 중요
- 사람 평가가 없으면 결론은 "시뮬레이션 상 개선"으로 제한

14. 실시간 적용 최종 방향
======================================================================

최종 목표는 휴대폰/PC 실시간 화면 보정.

하지만 현재 baseline을 매 프레임 그대로 돌리는 방식은 느릴 수 있음.

장기 구조:
- 개인 색각 분석은 최초 설정 때 1회
- 무거운 최적화는 학습/검증 때
- 실제 사용 중에는 경량 AI 추론 중심
- 화면 변화가 없으면 이전 결과 재사용
- 변경된 영역만 재계산 가능
- 시간적 안정성(temporal consistency) 필요

추후 loss 후보:
L_temporal = 이전 프레임과 현재 프레임의 보정량 변화 억제

목적:
같은 화면이 프레임마다 다른 색으로 미세하게 흔들리는 flicker 방지

R&E 단계에서는 실시간 제품 완성보다
"실시간 확장 가능성 + 처리시간 병목 측정"까지를 현실적 목표로 둔다.
