# Prischroma — 적록색약자를 위한 개인화 선택적 색보정

## 프로젝트 개요

적록색약 사용자가 **실제로 혼동하는 색 영역만** 선별해 최소한으로 보정하는 시스템.
기존 Daltonization 계열이 이미지 전체에 같은 변환을 적용해 불필요한 왜곡을 만드는 문제를
"선택적 보정 + 개인화"로 해결하는 것이 목표다.

2026 과학영재 창의연구 R&E · 팀 Prischroma (이창민 · 정인교 · 한정훈)

---

## 파이프라인과 담당

| 단계 | 담당 | 질문 | 출력 |
|---|---|---|---|
| ① 개인화 | 한정훈 | 이 사용자는 어떤 색을 혼동하는가 | `type`, `severity`, 개인 역치 |
| ② 탐지·측정 | **정인교 (이 세션)** | 이미지의 어디에서 혼동이 일어나는가 | 영역 쌍별 원본 수치 |
| ③ 보정 | 이창민 | 색을 얼마나 어느 방향으로 옮길까 | `ΔL, Δa, Δb` |
| ④ 평가 | 공동 | 기존 방법보다 나은가 | 정량 지표 + 사용자 평가 |

**이 저장소에서 작업하는 사람은 ② 담당(정인교)이다.**

## 핵심 기술 결정 (반드시 지킬 것)

### 1. 혼동 여부를 판정하지 않는다

②단계 출력에 `is_confused` 같은 0/1 판정을 넣지 않는다.
색차·거리·크기 **원본 수치만** 기록하고, 임계값 결정은 ①단계 사용자 실험 결과에 맡긴다.

배경: 한정훈의 실험에서 개인 역치 **0.62**가 측정되었으나, 이는 큰 색면 두 개를
맞붙여 비교한 최적 조건의 값이다. 노선도의 얇은 선이나 떨어진 영역에는 그대로 쓸 수 없다.
현재는 0.62를 **개인의 상대적 민감도**로만 쓰고, 실제 이미지용 기준은 추가 실험으로 정한다.

개발 중 임시로 쓰는 값(예: 3.0)은 **설정값으로만 두고 연구 결과로 서술하지 않는다.**

### 2. 시뮬레이터 정본은 `machado.py`

팀 baseline의 `machado.py`가 유일한 색각 시뮬레이터다. 41개 단위 테스트로 검증되어 있다.
같은 기능을 하는 별도 구현을 만들지 말 것. 과거 `cvd_simulation.py`가 있었다면 제거 대상이다.

### 3. severity는 임상 중증도가 아니다

`severity`는 Machado 모델의 내부 파라미터다. "이 사람은 중증도 0.8"이 아니라
"이 값을 넣었을 때 이 사람의 혼동 양상이 가장 잘 재현된다"는 의미다.
문서·주석·보고서에서 이 구분을 흐리지 않는다.

### 4. 색차는 CIEDE2000

RGB·HSV의 수치 거리는 지각 차이와 비례하지 않는다. 혼동 판정과 평가 모두 CIEDE2000을 쓴다.

### 5. 색 변환은 선형 RGB에서

sRGB 값을 그대로 행렬에 곱하지 않는다. 감마 복호화 → 변환 → 감마 부호화 순서를 지킨다.

## 저장소 규칙

### Git 워크플로

```
작업 시작 전  : Fetch origin → Pull origin
작업 종료 후  : Commit → Push (미루지 말 것)
```

**같은 파일을 여러 명이 동시에 수정하지 않는다.** 파일 소유권은 아래 표를 따른다.

### 파일 소유권

| 경로 | 소유 | 이 세션에서 |
|---|---|---|
| `src/machado.py` | 이창민 | **수정 금지** (읽기만) |
| `src/baseline.py` | 이창민 | **수정 금지** (호출만) |
| `src/two_color_demo.py` | 이창민 | **수정 금지** |
| `src/slic_extract.py` | 정인교 | 자유 |
| `src/measure_pairs.py` | 정인교 | 자유 |
| `src/export_tables.py` | 정인교 | 자유 |
| `src/generate_synthetic.py` | 정인교 | 자유 |
| `requirements.txt` | 공동 | 추가만, 제거는 상의 후 |

이창민 소유 파일에 변경이 필요하면 **직접 고치지 말고** 필요 사항을 정리해 전달한다.

### 커밋하지 않는 것

- 큰 데이터 (생성 이미지, 측정 JSON, 대용량 CSV)
- 개인정보 (피험자 응답 원본, 이름, 연락처)
- 가상환경 `.venv/`

`.gitignore`에 이미 반영되어 있다. 새 산출물을 만들면 용량을 확인하고 필요시 추가한다.
예외적으로 `results/conditions.md`는 수 KB이고 팀원이 필요로 하므로 커밋한다.

## 자주 쓰는 명령

```powershell
# 환경
cd src
pip install -r ../requirements.txt

# 테스트 (41개 통과해야 정상)
python -m unittest -q

# 두 색 혼동·보정 데모
python two_color_demo.py

# 실제 이미지 측정
python -c "from measure_pairs import measure_directory; measure_directory('../data/real/images','../results/measurements_real.json', n_segments=800)"

# CSV·통계 변환
python -c "from export_tables import export_all; export_all('../results/measurements_real.json','../results')"
```

`n_segments`는 얇은 선이 있는 이미지에서 **800 이상**을 쓴다.
예비 측정에서 2px 선이 300에서는 배경에 흡수되어 아예 검출되지 않았다.

## 알려진 한계 (보고서에 명시할 것)

1. **얇은 요소의 대표색 왜곡** — 안티앨리어싱으로 배경색이 섞여 실제 색과 달라진다.
   `stroke_width_px`가 작은 영역은 색 신뢰도가 낮다.
2. **SLIC 파라미터 의존** — `n_segments`가 작으면 얇은 선이 통째로 누락된다.
3. **공간 근사** — 비교 대상 쌍을 거리로 근사한다. 범례와 노선처럼 의미적으로
   연결되었으나 멀리 떨어진 쌍을 완전히 포착하지 못한다.
4. **배경 추정의 단순함** — 테두리에 닿은 가장 큰 영역을 배경으로 본다.
