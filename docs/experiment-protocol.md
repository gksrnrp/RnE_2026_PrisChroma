# 선 굵기별 색 구별 역치 실험 — 시작 전 고정 문서

연구 제목: **적록색각이상자를 위한 선 굵기별 색 구별 역치 예측 및 최소 색이동 보정**

이 문서는 사람 대상 시행을 시작하기 전에 조건과 분석 규칙을 고정하기 위한
체크리스트다. `미정`인 항목을 채우고 자극 생성 코드의 parameter recovery를
통과하기 전에는 본 시행을 시작하지 않는다. 큰 색 패치에서 얻은 0.62나 개발용
3.0을 선 자극의 정답 임계값으로 사용하지 않는다.

현재 `schemas/`와 `data/contracts/`의 버전은 `0.1-draft`이며 가짜 데이터만
허용한다. 세 팀원이 필드를 합의하기 전에는 1.0으로 올리거나 사람 자료를
수집하지 않는다.

## 1. 연구 질문과 범위

1. 같은 색쌍이라도 선의 굵기에 따라 적록색각이상 참가자의 C80이 달라지는가?
2. 한 굵기에서 짧게 교정한 개인값과 정상색각 선행모델의 상대적 굵기 함수를
   결합하면, 측정하지 않은 굵기의 개인 C80을 예측할 수 있는가?
3. 굵기별 C80을 보정 제약으로 사용하면 고정 임계값보다 필요한 색 변화량을
   정확하게 정할 수 있는가?

본 연구는 참가자 2명의 반복측정 사례연구다. protan/deutan 유형별 모집단 차이나
모든 화면·과제·굵기로 일반화하지 않는다. AI 모델 개발은 이번 연구의 필수 범위가
아니다.

## 2. 핵심 정의

- **주 좌표:** 참가자별로 고정한 Machado type/severity를 적용한 뒤의 ΔE00
  (`C80_sim`). 원본 ΔE00는 보조 좌표로 함께 저장한다.
- **C80:** 4지선다 과제에서 찍기와 실수를 포함한 실제 정답률이 80%에 도달하는
  시뮬레이션 후 ΔE00.
- **최소 색이동:** A만 이동, B만 이동, 둘 다 이동을 비교하여 제약을 만족하는
  후보 중 OKLab 총 이동 비용이 가장 작은 근사해. 수학적 전역 최적해는 아니다.
- **선행모델 역할:** Szafir(2018)의 선 모델은 정상색각·이진 동일/상이 과제의
  CIELAB 모델이므로 절대 확률이나 절대 C80을 가져오지 않는다. 고정한 Lab 방향의
  굵기별 **상대 배율**만 전이 모델 C에 사용한다.

## 3. 실험 전에 반드시 채울 값

| 항목 | 고정값 | 확인 방법 |
|---|---|---|
| 참가자 익명 ID | 미정 | 이름·학번을 코드/저장소에 넣지 않음 |
| CVD type과 Machado severity | 미정 | 큰 패치 실험의 독립 데이터에서 결정 후 동결 |
| 모니터 모델 | 미정 | 실험 장치 기록 |
| 화면 가로 길이(mm) | 미정 | 자로 직접 측정 |
| 가로×세로 해상도(px) | 미정 | 운영체제 설정 확인 |
| 배율 설정 | 미정 | 운영체제·브라우저 100% 여부 기록 |
| 관찰 거리(mm) | 미정 | 고정 장치 또는 거리 표시 사용 |
| 주변 조명 | 미정 | 같은 장소·밝기로 유지 |
| 배경색 | 미정 | sRGB와 실제 화면 설정 기록 |
| 선 길이·방향·끝모양 | 미정 | 굵기 외 요소 고정 |
| 안티앨리어싱 방식 | 미정 | 렌더러와 버전 기록 |
| 고정 Lab 방향 `u=(dL,da,db)` | 미정 | 결과를 보기 전에 한 방향으로 동결 |
| 측정 굵기 3개 | 미정 | px와 변환된 시각도를 모두 기록 |
| 주 시행 피드백 정책 | 미정 | 연습과 본 시행을 구분 |
| 계단 시작점·갱신 규칙 | 미정 | 시뮬레이션으로 회복 성능 확인 후 동결 |
| lapse 처리 | 미정 | 회복 실패 시 고정 또는 조건 간 공유 규칙 사전 선택 |

굵기는 px만 기록하지 않고 시각도로 환산한다. 변환은
`src/experiment_design.py`를 사용한다. Szafir 전이 모델을 비교하려면 시각도가
원 논문의 측정 범위 0.05~0.35도 안에 있어야 한다. 범위 밖 외삽은 주 결과로
사용하지 않는다.

## 4. 자극과 자료 분리

- 한 시행에서 기준 색의 Lab 중점과 색차 방향을 고정하고, 두 색을 중점의 양쪽으로
  대칭 이동시킨다. 그래야 색차 증가와 특정 색 자체의 변화가 덜 얽힌다.
- 색역 밖 후보는 버리고, 실제 표시된 8-bit sRGB와 Machado 시뮬레이션 결과를
  모두 저장한다.
- 참가자가 본 시행에 쓰인 색쌍과 검증 색쌍은 분리한다.
- type/severity를 정한 큰 패치 자료, 3개 굵기 모델 적합 자료, 미측정 굵기 검증
  자료를 서로 섞지 않는다.
- 세션·시행 순서·정답·응답·표시 RGB·원본/시뮬레이션 Lab·두 ΔE00·굵기 px/도·
  렌더링 시간·중단 여부를 원자료로 저장한다.

## 5. 측정과 모델 비교

### 교정 자료

참가자마다 굵기 3조건 × 조건당 96시행, 총 288시행을 기본 계획으로 한다.
parameter recovery에서 식별이 부족하면 실제 참가자 데이터를 보기 전에 lapse를
고정하거나 심리측정 기울기를 조건 간 공유하는 대체 규칙을 선택해 기록한다.

### 비교 모델

- **A:** 보편 고정 임계값.
- **B96:** 가운데 한 굵기의 96시행으로 적합한 개인별·굵기 불변 모델.
- **B288:** 세 굵기 288시행 전체로 적합한 개인별·굵기 불변 모델.
- **C:** 가운데 굵기 96시행으로 개인 배율을 맞추고 Szafir 상대 함수를 결합한
  저비용 전이 모델.
- **D:** 288시행 전체로 적합한 개인별 굵기 모델. 기본 후보는
  `log(C80)=alpha+beta*log(s)`이며 굵을수록 역치가 작아진다는 사전 방향은
  `beta<0`이다.

C와 B96은 같은 자료량에서 선행모델 전이의 이득을, C와 B288은 측정 비용의
이득을, D와 B288은 굵기 효과의 이득을 비교한다. 공유 기울기 가정은 굵기별
기울기 모델과 정보기준으로 사후 점검하되, 데이터가 부족하면 탐색적 분석으로만
표시한다.

### 미측정 굵기 검증

세 교정 굵기를 `s1<s2<s3`라 할 때 후보는 `sqrt(s1*s2)`와 `sqrt(s2*s3)`로
사전 고정한다. 288시행 적합 후 각 후보에서 모델 예측 차이 `delta`와 예측·측정
불확실성 반폭 `h`를 계산한다. `lower_CI(delta)>h`인 후보 중 비율이 큰 하나를
고르고, 어느 후보도 통과하지 못하면 억지로 우열을 주장하지 않고
**현재 정밀도로 모델 구분 불가**라고 보고한다. 후보 선택은 모델이 가장 갈리는
내삽 지점을 고른 것이므로 결론 범위를 3개 측정 굵기 사이로 제한한다.

기하평균이 소수 픽셀이면 그 값을 그대로 렌더링한 것으로 간주하지 않는다.
검증 응답을 보기 전에 가까운 서로 다른 정수 픽셀을 선택하고, 실제 렌더링 굵기의
시각도를 다시 계산해 기록한다. 소수 픽셀 안티앨리어싱을 쓰려면 그 렌더링 방식을
별도 조건으로 고정하고 결과 해석에 밝힌다.

선택한 굵기에서 60시행짜리 독립 계단을 3개 세션에 걸쳐 수행한다. 각 계단 C80의
변동계수 `CV=SD/mean`이 0.20 이하이면 역분산 가중으로 통합하고, 0.20을 넘으면
통합 우열을 내지 않고 세션별 결과와 불안정성을 보고한다. 실제 C80의 bootstrap
신뢰구간보다 모델 예측 차이가 작으면 역시 구분 불가로 판정한다.

## 6. 결과 판정

주 결과는 미측정 굵기 C80에 대한 각 모델의 절대 예측 오차와 그 불확실성이다.
Brier score와 calibration은 보조 결과다. 최소 색이동 보정에는 같은 색쌍 집합과
동일한 C80 제약을 사용하고, 성공한 방법들의 색 이동 비용과 과소·과잉 보정을
보조적으로 비교한다. 사람에게 보정 결과를 다시 읽게 하지 않았다면
‘가독성이 향상됐다’고 쓰지 않고 ‘모델 제약을 만족했다’고만 쓴다.

## 7. 중단·윤리 규칙

- 참가 동의와 필요 시 보호자·지도교사 승인을 받은 뒤 시작한다.
- 검사는 의학적 진단이 아니며 익명 ID만 저장한다.
- 세션당 시행 수와 휴식 기준을 미리 정하고, 중단 요청 시 즉시 종료한다.
- 중도 이탈에 대비해 각 단계가 부분 결론을 남기도록 세션 순서를 배치하되,
  검증 과제를 먼저 경험한 학습 효과는 세션별 추세로 확인한다.
- 분석 규칙을 바꿔야 하면 기존 결과를 보기 전에 이유와 변경 시점을 남긴다.

## 8. 실제 시작 순서

1. 공통 데이터 계약 `0.1-draft`를 가짜 데이터로 검증한다.
2. 위 표의 `미정` 항목과 4AFC 화면 구성을 팀 회의에서 확정한다.
3. 화면 물리값으로 후보 굵기의 시각도를 계산하고 Szafir 범위를 확인한다.
4. 자극 생성기와 JSONL 원자료 저장을 구현한다.
5. 가상 참가자로 parameter recovery를 수행한다.
6. 연습 시행으로 렌더링·키 입력·중단·저장을 점검한다.
7. 스키마·조건·분석 코드를 1.0으로 동결한 뒤 사람 대상 본 시행을 시작한다.
