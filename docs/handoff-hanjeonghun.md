# 실험·역치 추정 파트 인수인계 (한정훈)

선 굵기에 따라 색 구별 역치 C80 이 어떻게 달라지는지 재는 부분이다.
자극을 만들고, 사람에게 보여주고, 응답을 저장하고, 심리측정 함수를 적합해
C80 을 뽑는 데까지가 이 파트다.

---

## 1. 무엇이 들어 있나

| 파일 | 하는 일 |
|---|---|
| `src/experiment/psychometric.py` | 심리측정 함수와 C80 의 정의 |
| `src/experiment/stimulus.py` | 선 자극과 색쌍 생성, 색역 검사, 시야각 변환 |

| `src/experiment/fit_c80.py` | 격자 최대가능도 적합, 부트스트랩, 세션 통합 규칙 |


## 2. 핵심 정의

**C80 = 정답률이 80% 가 되는 색차.** 여기서 색차는 원본 색차가 아니라
**Machado 시뮬레이션을 통과한 뒤의 ΔE00** 다. 그 사람 눈에 실제로 도달하는
차이를 재야 하기 때문이다.

4지선다이므로 찍어도 25% 는 맞는다. 그 몫을 빼고 본다.

```
p(정답 | x) = 0.25 + (0.75 − λ) · 로지스틱((x − θ) / w)
```

λ 가 0.20 을 넘으면 천장이 0.80 아래로 내려가 C80 이 아예 존재하지 않는다.
그 경우 코드는 값을 지어내지 않고 `None` 을 돌려준다.

## 3. 실행법

### 교정 측정 (굵기 3개, 고정자극)

```bash
cd src && python -m experiment.runner --participant P01 --mode calibration --cvd-type protan --severity 0.94 --severity-source patch_session_PO3 --widths 3,7,16 --trials-per-width 96 --expected-c80 4.0 --screen-diagonal 15.6 --viewing-distance 50
```

### 검증 측정 (굵기 1개, 계단 3세션)

```bash
cd src && python -m experiment.runner --participant P01 --mode validation --cvd-type protan --severity 0.94 --severity-source patch_session_PO3 --validation-width 5 --staircase-id S1 --staircase-trials 120 --screen-diagonal 15.6 --viewing-distance 50
```

`--staircase-id` 를 S1, S2, S3 로 바꿔 세 번 돌린다. 같은 파일에 이어 쌓이고
세션별로 구분되어 저장된다.

중간에 ESC 로 끊어도 그때까지가 남는다. 같은 명령을 다시 치면 남은 시행부터
이어서 한다. 끝난 세션을 다시 실행하면 아무것도 하지 않는다.

## 4. 사람 실험 전에 이미 확인한 것

모의검증(`parameter_recovery.py`) 결과. 가상 참가자 네 명, 각 300 회 반복.

| 참값 | 참 C80 | 추정 C80 | 편향 | 상대SD |
|---|---|---|---|---|
| 예민·급격 | 1.86 | 1.82 | −2% | 0.114 |
| 보통 | 4.30 | 4.28 | −0% | 0.180 |
| 둔감·완만 | 8.86 | 9.00 | +2% | 0.180 |
| 실수 많음 | 4.93 | 4.91 | −0% | 0.276 |

**판정: 96 시행, θ·w·λ 자유 추정으로 진행 가능.**

- λ 를 0.05 로 고정하는 대안은 채택하지 않는다. 실수가 잦은 사람에서
  오히려 편향이 17% 로 커졌다.
- 굵기 간 기울기 공유(`fit_shared_w`)는 예비로 남겨 두되 주 분석이 아니다.
- 시행 수와 정밀도: 48 → 0.267, 96 → 0.171, 144 → 0.133, 192 → 0.101.

## 5. 아직 정하지 않은 것과 그 이유

### 5-1. 선 굵기 값

**아직 코드에 박아두지 않았다.** 인교의 이미지 선 굵기 통계가 나온 뒤
5 단계에서 정하기로 했기 때문이다. `--widths` 로 넘긴다. 검사
`test_widths_are_not_hard_coded_in_the_stimulus_module` 가 이걸 지킨다.

정할 때 지켜야 할 장치 한계:

- 15.6 인치 1920 폭, 50 cm 거리에서 3 / 7 / 16 px = **0.062 / 0.144 / 0.330 도**
- 이보다 가늘면 화면 화소보다 작아지고, 굵으면 선이 아니라 면이 된다.
- **px 를 그대로 쓰지 말고 항상 시야각을 함께 기록한다.** 다른 화면에서
  같은 px 는 다른 크기다. `stroke_width_deg` 필드가 그 용도다.

### 5-2. 색 변화 방향

기본값은 CIELAB a\* 축, 중심색 L=55, a=6, b=14 이다. 확정 전에 반드시
`check_axis` 로 확인해야 한다.

**혼동축을 고르면 안 된다.** 그 사람 눈에는 아무리 벌려도 색차가 0 근처에
머물러 C80 에 도달하지 못한다. protan 0.94 기준 도달 가능한 최대 색차:

| 방향 | 최대 시뮬 ΔE00 |
|---|---|
| a\* 축 (적록) | 15.90 |
| b\* 축 (황청) | 48.46 |
| L\* 축 (명도) | 71.55 |

C80 이 4 근처라면 a\* 축으로 충분하다. 실행 시 자동으로 검사하고, 여유가
부족하면 시작하지 않는다.

### 5-3. 검증 굵기

교정 굵기 **바깥**에 두어야 한다. 안쪽(내삽)에 두면 후보 모델들이 거의 같은
값을 내서 우열이 안 갈린다. `compare_models.divergence` 로 미리 확인한다.

## 6. 반드시 읽어야 할 경고

### 6-1. 계획서의 60 × 3 세션으로는 모델을 가를 수 없다

후보 모델의 예측이 검증점에서 **8.7% / 6.8%** 밖에 안 벌어지는데,
60 × 3 세션의 C80 측정 표준편차는 **9.6%** 다. 예측 차이가 측정 오차에
묻힌다. 어떤 결과가 나오든 "어느 모델이 맞다"고 말할 수 없다.

**120 × 3 이 필요하다** (SD 6.5%). 이 판단은 자료를 보기 전에 내렸고,
`required_trials()` 에 계산이 들어 있다. 시행 수를 늘릴 수 없다면 검증
굵기를 예측이 더 벌어지는 쪽으로 옮겨야 한다.

`compare_models.compare()` 는 구분 불가능한 조건이면 `resolvable: false` 를
붙이고 "이 굵기에서는 모델 우열을 확정하지 않는다"고 출력한다.

### 6-2. 큰 색 패치 실험의 0.62 를 선 자극 임계값으로 쓰지 않는다

앞서 큰 패치로 잰 값이다. 선은 조건이 다르므로 그대로 옮기면 안 된다.
이 실험을 하는 이유가 바로 그것이다.

### 6-3. 개발용 severity 3.0 은 결과에 쓰지 않는다

Machado severity 는 0.0~1.0 이다. 3.0 은 코드 확인용이다.

### 6-4. "가독성이 좋아졌다"고 쓰지 않는다

이 실험이 재는 것은 **색을 구별할 수 있는 최소 색차**다. 보정한 그림이
읽기 쉬워졌는지는 사람을 대상으로 한 별도의 사후 실험이 있어야 말할 수 있다.

### 6-5. 세션이 서로 다르면 합치지 않는다

계단 세 세션의 C80 변동계수가 0.20 을 넘으면 통합하지 않는다. 세션별로
보고하고, 그 굵기에서는 모델 우열을 확정하지 않는다.
(`fit_c80.combine_staircases`)

## 7. 다른 사람에게 필요한 것

### 창민에게

- `simulate_color_float` 의 확정 스키마. 지금은 `machado.py` 를 직접
  가져다 쓰고 있다. 인자 순서나 severity 처리가 바뀌면 알려 달라.
- 원자료 JSONL 필드 이름을 팀 스키마와 맞출 것.
  현재 `schema_version` 은 `"1.0"`.

### 인교에게

- **이미지에서 실제로 쓰이는 선 굵기의 분포** (중앙값과 사분위수).
  이게 있어야 교정 굵기 3개와 검증 굵기 1개를 정할 수 있다. 지금 코드는
  값이 비어 있는 상태로 대기 중이다.
- 굵기는 px 가 아니라 **원본 이미지 대비 비율이나 시야각**으로 달라.

### 나(한정훈)에게 남은 것

- **참가자 모집이 임계 경로다.** protan 과 deutan 이 모두 필요한데
  지금 확보된 것은 1 명뿐이다. 나머지는 코드가 다 되어 있어서 사람만
  오면 바로 돌아간다.
- 굵기 확정 후 `results/participant_thresholds.json` 생성. 자료가 없어
  아직 만들지 못했다.

## 8. 원자료 취급 규칙

- 원자료에 **이름·학번을 저장하지 않는다.** 참가자는 P01 같은 코드로만
  기록한다. 검사 `test_raw_data_contains_no_personal_information` 이 지킨다.
- **원자료와 개인정보는 GitHub 에 올리지 않는다.** `data/` 는 로컬에만 둔다.
- 각자 자기 담당 파일만 고친다. 이 파트는 `src/experiment/` 와
  `src/test_*.py` 다.

## 9. 실험 진행 시 지킬 것

- 모니터를 sRGB 모드로 두고, 야간 모드와 자동 밝기를 끈다.
  실행기가 시작 전에 확인 화면을 띄운다.
- 밝기와 조명을 세션마다 같게 유지한다. 바뀌면 기록에 남긴다.
- 화면까지의 거리를 고정하고 `--viewing-distance` 로 넘긴다.
- 연습 시행에는 정오 표시가 있고 **본 시행에는 없다.** 본 시행에서
  피드백을 주면 참가자가 학습해 역치가 낮아진다.
- 안티앨리어싱은 꺼져 있다. 가는 선의 가장자리에 배경색이 섞이면 기록된
  색이 실제와 달라지기 때문이다.
