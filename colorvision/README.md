# colorvision — 색쌍 구별 실험 및 개인화 파라미터 추정

R&E 1차 역할분담 중 **2번 (한정훈)** 파트.
사용자에게 색쌍 구별 테스트를 시행하고, 그 응답으로부터 개인화 파라미터
`{type, severity, confusion_threshold}` 를 추정한다.

이 파라미터가 3번(정인교)의 영역 정보와 함께 1번(이창민)의 혼동 판정 및
최소 색이동 모듈로 넘어간다.

## 실험 절차

한 시행에서 2×2 로 네 칸을 보여주고, 색이 다른 하나를 고르게 한다 (4지선다).
마우스 클릭 또는 숫자키 1/2/3/4.

두 색은 기준색 `c` 에서 방향 `d` 로 `±t/2` 만큼 벌린 것이다.
`t` 를 계단법(1-up/2-down)으로 조절해 그 사람의 구별 경계를 찾는다.
조건 12개를 무작위로 섞어 진행하며, 총 200시행 안팎 / 10분 정도 걸린다.

**8% 는 아주 쉬운 확인용 시행**이다. 여기서 정답률이 낮으면 집중이 흐트러진
것이므로, 추정할 때 실수율 λ 로 흡수된다.

확인용 시행은 **모든 유형이 잘 보는 별도 색쌍 하나**를 쓴다 (어떤 유형에서도
지각 ΔE00 이 20 이상). 각 조건의 최대 색차를 쓰면 혼동축 조건의 확인용
시행이 해당 유형에게는 여전히 불가능해서, 집중도가 아니라 색각이상을 재게
되고 λ 가 부풀려진다. 실제 피험자 데이터에서 이 문제가 드러나 고쳤다 —
그 이전에 수집한 데이터는 옛 방식이며, 분석할 때 경고가 함께 출력된다.

확인용 색쌍에는 **밝기 제약**도 걸려 있다 (두 색 모두 L\* 35~72, 차이 12 이하).
제약이 없으면 거의 검정에 가까운 패치가 뽑혀 나머지 시행과 확연히 달라 보이고,
피험자가 "이건 확인용이구나"를 알아채 버린다.

### 기준색 흔들기 (jitter)

같은 기준색 12개가 계속 나오면 눈이 적응하고 피험자가 패턴을 외운다.
그래서 매 시행 기준색을 **측정 방향에 직교하는 방향으로** 조금씩 옮긴다.
직교 방향이라 두 색의 간격(= 재는 값)은 그대로다. 추정은 시행마다 실제로
보여준 색을 그대로 쓰므로 계산도 정확하다.

가상 관찰자로 폭을 정했다:

| jitter | 색 다양성 | 유형 적중 | severity 오차 |
|---|---|---|---|
| 0.000 | 30% | 100% | 0.067 |
| 0.035 | 99% | 100% | 0.065 |
| **0.070** | **100%** | **100%** | **0.054** |
| 0.120 | 100% | 96% | 0.050 |

0.07 까지는 정확도 손해가 없고 오히려 severity 추정이 나아진다 (색 공간을 더
넓게 훑기 때문). 그 이상은 유형 판정이 흔들린다. `--jitter 0` 으로 끌 수 있다.

### 배치 흔들기

`--varied-layout` 을 주면 패치의 **위치, 크기, 모양**도 매 시행 새로 뽑는다.
기본은 아니다 — 배치를 바꾸면 사람의 역치가 달라질 수 있는데 그걸 검증할
방법이 없어서, 색만 바꾸고 배치는 고정해 둔다.

단, **한 시행 안에서는 네 패치의 크기와 모양이 모두 같다.** 정답 패치만 작거나
원이면 판단 난이도가 달라져 4지선다가 공정하지 않게 된다. 시행이 바뀔 때마다
새로 뽑으므로 화면은 매번 달라진다.

패치는 화면을 2x2 로 나눈 칸 안에서만 움직이므로 절대 겹치지 않는다.
가장자리는 안티에일리어싱을 **쓰지 않는다** — 부드럽게 만들면 배경색이 섞여
그 픽셀의 색이 달라지는데, 이 실험은 그 색 자체를 재기 때문이다.

기본은 고정 2x2 이고, `--varied-layout` 으로 켠다.

> 배치가 바뀌면 사람의 역치도 조금 달라질 수 있다. 이건 시뮬레이션으로
> 검증할 수 없는 부분이다 (가상 관찰자는 화면을 보지 않는다). 고정 배치로
> 수집한 세션과 비교할 때는 이 점을 감안할 것. 그래서 기본은 고정 2x2 다.

### 주요 옵션

```bash
python -m colorvision.experiment --participant P01 --windowed   # 창 모드
python -m colorvision.experiment --participant P01 --max-trials 24  # 더 정밀하게
python -m colorvision.experiment --participant P01 --no-feedback    # 정오 표시 끄기
```

## 1번 파트로 넘기기

이창민 파트의 `config.ConfusionThresholds` 는 ΔE00 임계값 세 개를 요구하고,
일부러 기본값을 두지 않는다 ("임계값은 사용자 실험으로 조정해야 한다").
그 세 값을 채우는 것이 이 파트의 최종 산출물이다.

```bash
python -m colorvision.handoff data/P01_..._params.json --json
```

임계값은 심리측정 함수를 뒤집어서 얻는다. 찍기(γ)와 실수(λ)를 뺀 **순수 구별
확률** `P(구별) = σ((d-θ)/w)` 를 뒤집으면 "구별 확률이 p 가 되는 색차" 가 나온다.

```
simulated_max = d(25%)   넷 중 하나꼴로만 가려지면 혼동으로 본다
target        = d(95%)   이만큼 벌리면 거의 항상 가려진다
original_min  = 3.0      잠정값 (2017 논문). 정상 색각 측정이 생기면 교체
```

λ 를 빼는 이유가 하나 더 있다. 실수율이 조금만 높아도 정답률 천장이 0.93 같은
값이 되어 "정답률 95%" 라는 목표가 도달 불가능해진다.

### ⚠️ 실험실 역치와 이미지 역치는 다르다

측정된 세션(PO3)에서 나온 값은 `simulated_max = 0.62`, `target = 1.83` 이다.
2017 논문이 쓴 3 보다 훨씬 작다. 이유는 측정 조건이다 — 큰 균일 패치를 나란히
놓고 시간 제한 없이 고르게 했으므로 **가장 좋은 조건의 값**이다. 실제 이미지의
얇은 선, 작은 글씨, 텍스처 위에서는 이보다 나쁘다.

실제로 protan 혼동선 위의 색쌍 132개를 만들어 보면 시뮬 ΔE00 이 0.36~2.77
(중앙값 0.69) 에 퍼져 있는데, 0.62 를 쓰면 43% 만 혼동으로 잡히고 3.0 을 쓰면
100% 가 잡힌다. **어느 쪽이 맞는지는 이미지 단위 실험으로 답할 문제다**
(실행계획 §12 의 τ 값 미해결 항목).

당장은 `--margin` 으로 여유를 줄 수 있다. 다만 배수를 얼마로 할지에 근거가
아직 없으므로, 이 역치를 **개인 간 상대 민감도**로 쓰는 편이 안전하다 —
θ 가 1.0 인 사람과 3.0 인 사람은 민감도가 3배 다르다는 정보는 확실하다.

### 통합 확인 결과

`handoff.py` 가 낸 값을 그대로 `run_baseline` 에 넣어 확인했다.

```
#92b748 vs #b9b248   원본 ΔE00 10.5 -> 시뮬 0.35   혼동 판정 True
  (146,183,72) 유지 / (185,178,72) -> (187,178,59)
  보정 후 시뮬 ΔE00 1.84   (목표 1.83 달성)
```

한쪽만 움직이고 다른 쪽은 그대로 두는 분담 선택까지 의도대로 작동한다.

## 추정이 어떻게 작동하는가

실행계획 v4 §3-3 그대로다. 이시하라로 유형을 **확정하지 않고**, 실제 응답을
가장 잘 설명하는 시뮬레이터를 고른다.

후보 파라미터 `(type, s)` 에서 그 사람이 느낄 색차는

```
d = ΔE00( Sim(c1; type, s),  Sim(c2; type, s) )
```

이고, 4지선다이므로 정답 확률은

```
P(정답) = 0.25 + (0.75 - λ) · σ((d - θ) / w)
```

`(type, s, θ, w, λ)` 를 격자 탐색으로 최대가능도 추정한다.
`normal`(색각이상 아님) 모델도 후보에 넣어 비교하므로, "이상이 아니다"라는
결론도 나올 수 있다.

출력에는 protan / deutan / normal 각각의 로그가능도와 그 차이(ΔLL)가 함께
나온다. **ΔLL 이 2.3 미만이면 유형 판정 근거가 부족하다**고 보고한다.

## 왜 색쌍을 최적화해서 골랐는가

이 파트에서 가장 오래 걸린 문제다.

색쌍을 적당히 고르면 **protan 과 deutan 이 구별되지 않는다.** 두 유형의
혼동선 방향이 14.6도밖에 안 떨어져 있어서, severity 가 낮으면 두 모델이
예측하는 역치 패턴이 전체 배율만 다르고 모양이 거의 같아진다. 그러면
"protan 이고 severity 0.68" 과 "deutan 이고 severity 0.60" 이 같은 응답을
똑같이 설명해 버린다. 초기 설계에서 실제로 참값 deutan 을 protan 으로
뒤집어 추정했다.

`design.py` 는 **severity 를 어떻게 맞춰 끼워도 두 유형이 서로를 흉내내지
못하도록** 로그역치 패턴의 모양 차이를 최대화하는 조건 12개를 고른다.
고른 결과에 빨강 계열과 파랑/보라 계열이 함께 들어가는데, 이는 protan 이
장파장(빨강) 쪽 휘도 감도가 떨어진다는 점을 자극이 실제로 건드린다는 뜻이다.

### 색이 겹치지 않게 하는 제약

식별력만 보고 고르게 두면 **거의 같은 빨강을 5개씩 뽑는다.** 빨강이 P/D 를
가장 잘 가르기 때문에, 최적 색 하나를 찾은 뒤 그 주변만 계속 집는 것이다.
첫 설계에서 실제로 ΔE00 이 **1.3** 밖에 안 되는 빨강 쌍이 들어갔다. 피험자
입장에서는 몇 가지 색이 200번 반복되는 지루한 실험이 되고, 같은 색에 눈이
적응하기도 한다.

그래서 고른 기준색끼리 최소 ΔE00 을 강제한다. 값별 실측:

| 최소 색차 | 식별력 | 실제 색 최소 ΔE00 | s=0.3 유형적중 | s≥0.6 유형적중 |
|---|---|---|---|---|
| 없음 | 0.492 | 1.3 | 100% | 100% |
| **12** | **0.457** | **12.4** | **88%** | **100%** |
| 20 | 0.407 | 20.2 | 62~75% | 100% |
| 25 | 조건 12개를 채우지 못함 | | | |

12 로 정했다. 색은 확실히 구별되면서 성능 손해는 경증(s=0.3) 구간에만 조금
남는데, 그 구간은 원래 원리적 한계에 걸려 있고 추정기가 ΔLL 로 스스로
불확실하다고 보고한다.

> 이 표 자체가 **"자극 설계가 추정 성능을 좌우한다"** 는 R&E 실험 결과다.

조건을 다시 뽑으려면:

```bash
python -m colorvision.design            # 재최적화 (몇 분)
python -m colorvision.design --report   # 저장된 설계 확인
```

> `conditions.json` 은 **한 번 고정하면 바꾸지 말 것.** 피험자마다 다른
> 자극을 쓰면 서로 비교할 수 없다. 확인용 시행을 고칠 때도 조건 12개는
> 그대로 두고 `catch_condition` 항목만 추가했다.

## 2차 실험 — 기하 조건별 역치 (인교 데이터 대기 중)

실험실 역치(ΔE00 약 1)를 이미지 보정 기준으로 그대로 쓸 수 없다는 것이
확인되어(위 참조), 화면 조건을 바꿔가며 역치가 어떻게 변하는지 재는 실험을
붙여 두었다. **정인교 파트의 실측 통계가 오면 조건 값만 채우면 된다.**

| 파일 | 역할 |
|---|---|
| `geometry.py` | 크기·모양·거리·배경 프리셋. **지금 값은 전부 잠정** |
| `experiment_geometry.py` | (색 조건 x 기하 조건) 마다 계단법 하나 |
| `analyze_geometry.py` | 조건별 역치와 기준 대비 비율 + 부트스트랩 구간 |

```bash
python -m colorvision.experiment_geometry --participant P05     --type protan --severity 0.95 --viewing-distance 60 --screen-diagonal 24
python -m colorvision.analyze_geometry data/P05_..._geom_trials.csv     --type protan --severity 0.95 --plot --json
```

### 설계에서 배운 것 세 가지

**1. 색 조건 선택 기준이 본 실험과 정반대다.** 본 실험은 유형을 가르려고
혼동축 조건(그 유형에게 거의 안 보이는 색)을 골랐다. 그런 조건은 최대로
벌려도 지각 ΔE00 이 1 을 못 넘는다 — `c01_plane000` 은 protan 0.95 에서
최대 0.85 다. 역치가 3 으로 커지는 조건에서 쓰면 화면이 낼 수 있는 한계를
넘어 아예 측정이 안 된다. 그래서 여기서는 **여유가 큰 조건**을 고른다.

**2. 유형과 severity 는 고정한다.** 화면 조건에 따라 변할 리 없는 값인데
자유롭게 두면 기하 효과를 severity 가 흡수해 정작 보려는 변화가 가려진다.

**3. 색 조건 3개 미만이면 결과가 튄다.** 가상 관찰자로 잰 결과:

| 설정 | 총 시행 | 기하 조건당 | 평균 편향 | 상대 SD |
|---|---|---|---|---|
| 기하6 x 색2 x 14 | 179 | 30 | 불안정 | 1.34 |
| **기하6 x 색3 x 14** | **270** | **45** | **-8%** | **0.71** |
| 기하4 x 색3 x 14 | 178 | 45 | -13% | 0.86 |

한 세션의 배수는 상대 SD 0.7 수준으로 흔들린다. **「2배와 5배」는 갈라도
「2배와 2.5배」는 못 가린다.** 점추정값만 쓰지 말고 부트스트랩 구간을 함께
보고, 결론이 필요하면 세션을 여러 번 모을 것.

```bash
python -m colorvision.virtual --geometry-recovery --type protan --severity 0.95
```

### 시야각을 꼭 기록할 것

px 는 그 자체로 의미가 없다. 같은 6px 선도 화면 크기와 보는 거리에 따라

## 알려진 한계 — 보고서에 반드시 적을 것

1. **경증(severity ≲ 0.3)에서는 유형 판정이 원리적으로 어렵다.**
   두 유형 모두 정상 색각에 가까워지므로 어떤 색쌍을 골라도 구별 정보가
   거의 없다. `design.py --report` 가 severity 별 식별력을 출력한다.
   추정 결과의 ΔLL 이 낮게 나오면 "유형 미확정"으로 보고하는 것이 맞다.

2. **복원 검증은 추정기가 자기 자신의 생성 모델을 되찾는지 본 것이다.**
   실제 사람의 색 지각이 이 모델(Machado + ΔE00 + 로지스틱)을 따른다는
   근거는 아니다. 절차와 정보량의 검증이다.

3. **(유형, severity) 2차원이 개인차를 충분히 표현한다는 보장이 없다.**
   실행계획 §3-4 의 한계 그대로다.

4. **8비트 화면 한계.** 이 실험의 역치는 8비트 계조 한두 단계까지 내려간다.
   그냥 그리면 두 패치가 같은 픽셀값이 되어 아무도 못 맞히는 시행이 생기므로,
   패치를 미세 디더링으로 그린다 (`--no-dither` 로 끌 수 있으나 권장하지 않음).
   모니터 감마와 색역이 sRGB 에서 크게 벗어나면 결과가 흔들린다.
   **모든 피험자를 같은 모니터에서 측정하는 것이 안전하다.**

5. **`severity` 가 1.00 으로 나오면 격자 상한에 붙은 것이다.** "정확히 1.0"이
   아니라 "1.0 이상, 이 모델이 표현할 수 있는 최대"로 읽어야 한다.
   추정 결과에 경고가 함께 출력된다.

6. **이 프로그램은 임상 검사가 아니다.** 결과를 진단으로 쓰면 안 된다.
   개인화 파라미터를 얻기 위한 도구다.

7. **실제 피험자 실험은 지도교사 확인과 보호자 동의 절차를 거친 뒤에 한다.**
   그 전까지는 `virtual.py` 로만 검증한다.
